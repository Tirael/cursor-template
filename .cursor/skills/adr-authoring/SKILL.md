# Architecture Decision Records (Skill)

## Когда применять

- Есть несколько равноценных вариантов и нужен след решения
- Решение влияет на несколько модулей/команд
- Решение влияет на NFR (безопасность, доступность, производительность)

## Где хранить

- Реестр решений: `adr-architecture-decisions.md`

## Минимальный шаблон записи

- **Контекст**: какая проблема и ограничения
- **Варианты**: 2–3 альтернативы
- **Решение**: что выбрано и почему
- **Последствия**: что станет проще/сложнее

## Пример записи

### ADR-001: Выбор брокера сообщений

**Статус:** Принято

**Контекст:**
Нужен асинхронный обмен событиями между микросервисами.
Требования: гарантия доставки, порядок сообщений в партиции, масштабируемость.

**Варианты:**

1. RabbitMQ — проще в эксплуатации, меньше throughput
2. Kafka — высокий throughput, сложнее эксплуатация, retention
3. Redis Streams — простой, но слабее гарантии

**Решение:**
Kafka. Обоснование: высокий throughput, гарантии порядка в партиции,
retention для replay, Schema Registry для контрактов.

**Последствия:**

- (+) Масштабируемость и throughput
- (+) Возможность replay событий
- (−) Сложность эксплуатации (ZooKeeper/KRaft, партиционирование)
- (−) Latency выше, чем у RabbitMQ для малых объёмов
