# Capacity Planning (Skill)

## Когда применять

- Перед проектированием инфраструктуры и лимитов
- Перед вводом новых тяжёлых функций (поиск, экспорт, отчёты)
- Перед публичным релизом

## Артефакты

- Таблица сценариев нагрузки (RPS, payload, p95/p99)
- Лимиты и квоты (per tenant, per user, per endpoint)
- План нагрузочного тестирования (цели, метрики, критерии)

## Правила

- Нагрузка описывается сценариями, а не "средней температурой".
- Деградации описывать заранее (что отключаем первым).
- Масштабирование: stateless + очереди для тяжёлого.

## Шаблон таблицы нагрузки

| Сценарий | RPS (норма) | RPS (пик) | Payload | p95 цель | Примечание |
| -------- | ----------- | --------- | ------- | -------- | ---------- |
| Просмотр каталога | 100 | 500 | 2 KB | 500 мс | кэш 5 мин |
| Поиск | 50 | 200 | 1 KB | 800 мс | отдельный индекс |
| Добавление в корзину | 20 | 100 | 0.5 KB | 300 мс | — |
| Оформление заказа | 5 | 30 | 2 KB | 2 сек | PSP latency |
| Экспорт отчёта | 0.1 | 1 | 10 MB | 30 сек | async job |

## Шаблон квот

| Ресурс | Per tenant | Per user | Per endpoint |
| ------ | ---------- | -------- | ------------ |
| API requests | 10000/мин | 100/мин | — |
| Concurrent connections | 1000 | 10 | — |
| Export jobs | 10 одновр. | 2 одновр. | — |
| File upload | 100 MB/файл | — | — |

## Graceful degradation (приоритеты)

1. **Критичное** (не отключаем): оформление заказа, доступ к библиотеке
2. **Важное** (отключаем последним): поиск, каталог
3. **Второстепенное** (отключаем первым): рекомендации, экспорт отчётов
