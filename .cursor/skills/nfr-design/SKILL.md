# NFR Design (Skill)

## Когда применять

- Переводим ожидания бизнеса в измеримые NFR
- Выбираем SLO/SLI и бюджеты ошибок
- Определяем деградации и лимиты

## Где хранить

- Core минимум: `.cursor/rules/nfr-core.mdc`
- Полная версия: `nfr-requirements.md`

## Правила

- NFR должны быть измеримыми (p95/p99, RTO/RPO, SLO).
- Для "пиков" описывать graceful degradation и приоритеты функций.
- Любые изменения NFR должны отражаться в core и в полной версии.

## Пример SLO/SLI таблицы

| Сервис | SLI | SLO | Бюджет ошибок |
| ------ | --- | --- | ------------- |
| API Gateway | Доступность (% успешных ответов) | ≥99.9% за 30 дней | 43 мин/мес |
| Catalog API | Латентность p95 | ≤500 мс | — |
| Search | Латентность p95 | ≤800 мс | — |
| Orders API | Латентность p95 | ≤1 сек | — |
| Payments | Успешность транзакций | ≥99.5% | 0.5% ошибок |
| Library | Доступность файлов | ≥99.9% | 43 мин/мес |

**Метрики для алертов:**

- Error rate >1% за 5 мин → warning
- Error rate >5% за 5 мин → critical
- p95 latency >2× SLO за 10 мин → warning
