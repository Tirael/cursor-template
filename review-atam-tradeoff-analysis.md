# Рецензия: skill `atam-tradeoff-analysis` (v1.0)

> Анализ на полноту, применимость к контексту EBookStore
> и непротиворечивость с Core-документами и существующими skills.

## Общая оценка

Skill качественно спроектирован, опирается на классическую методологию ATAM
(Architecture Tradeoff Analysis Method), адаптированную под AI-assisted workflow.
Структура логична, шаблоны конкретны и применимы. Ниже приведены замечания
с разделением на **критические**, **существенные** и **рекомендательные**.

---

## 1. Полнота

### 1.1 Что покрыто хорошо

- **Процесс (9 шагов)** — корректная упрощённая адаптация ATAM: от определения
  scope до фиксации решения. Все ключевые фазы ATAM (бизнес-драйверы, utility tree,
  анализ подходов, sensitivity/tradeoff points, risks) присутствуют.
- **Шаблон quality-attribute scenario** — содержит все 6 элементов классического
  сценария качественного атрибута (источник, стимул, окружение, артефакт,
  ответ, мера ответа). Полностью соответствует SEI-шаблону.
- **Шаблон risks/non-risks** — подробный, с полем «Как проверим», что помогает
  перейти от теории к конкретным экспериментам.
- **Чек-лист качества** — привязан к Core NFR и неизменным правилам проекта.
- **Входы/выходы** — явно перечислены SSOT-источники и целевые артефакты.

### 1.2 Замечания по полноте

| # | Уровень | Замечание | Рекомендация |
|---|---------|-----------|-------------|
| P-1 | Существенное | Нет шаблона **utility tree** как табличного артефакта. В разделе «Выходы» он упомянут, в процессе (шаг 4) описан текстом, но формат/таблица отсутствует — в отличие от двух других шаблонов. | Добавить шаблон таблицы utility tree (атрибут / сценарий / приоритет H/M/L / сложность H/M/L). |
| P-2 | Существенное | Нет шаблона **итоговой таблицы сравнения вариантов** (decision matrix). Шаг 5 требует «описать подходы/тактики», шаг 9 — «выбрать вариант», но формат сравнения не дан. | Добавить шаблон сравнительной таблицы (вариант / сценарий / оценка / комментарий). |
| P-3 | Рекомендательное | Раздел «Когда применять» не указывает **когда не применять** (например, для тривиальных решений внутри одного контекста достаточно ADR без полного ATAM). | Добавить раздел «Когда НЕ применять» или уточнение порога сложности. |

## 2. Применимость к контексту EBookStore

### 2.1 Соответствие домену

- Skill **корректно применим** к задачам EBookStore: выбор стратегии кэширования
  каталога, выбор между sync/async при оформлении заказа, стратегия поиска
  (Elasticsearch vs PostgreSQL FTS) и другие типовые архитектурные решения.
- Привязка к `tradeoffs.md` логична — каталог компромиссов содержит именно те
  категории (consistency, caching, CQRS, queues, retries), по которым возникают
  архитектурные развилки.
- Привязка к `adr-architecture-decisions.md` корректна — ATAM-анализ
  является входом для ADR.

### 2.2 Замечания по применимости

| # | Уровень | Замечание | Рекомендация |
|---|---------|-----------|-------------|
| A-1 | Существенное | Не описана **связь с другими skills в рабочем процессе**: когда именно запускать ATAM относительно `nfr-design`, `capacity-planning`, `adr-authoring`. Skill существует «в вакууме», хотя в `system-design` он добавлен в карту задач. | Добавить раздел «Место в рабочем процессе» с указанием: выполняется после `nfr-design` + `capacity-planning`, результат передаётся в `adr-authoring`. |
| A-2 | Существенное | В `system-design/SKILL.md` skill добавлен в **карту задач** (таблица), но **не включён в «Минимальный порядок работы»** (пронумерованный список из 11 шагов). Это создаёт неоднозначность: skill зарегистрирован, но не встроен в pipeline. | Добавить `atam-tradeoff-analysis` в порядок работы между шагами 9 (`capacity-planning`) и 10 (`adr-authoring`). |
| A-3 | Рекомендательное | Нет **примера** применения skill к конкретной задаче EBookStore (аналогично примеру ADR-001 в `adr-authoring`). Пример ускорил бы onboarding. | Добавить пример: ATAM-анализ для выбора стратегии обработки платежей (sync callback vs async webhook). |

## 3. Непротиворечивость

### 3.1 Соответствие Core-документам

Проверены все ссылки и утверждения skill на соответствие:

- **`project-core.mdc` (v1.0)** — непротиворечив. Skill корректно ссылается
  на версию и дату. Неизменные правила (8 пунктов) из `project-core.mdc`
  отражены в чек-листе качества skill (tenantId, ABAC, audit_log, Vault, mTLS,
  outbox, retry/backoff + CB, async >5 сек).
- **`nfr-core.mdc` (v1.0)** — непротиворечив. Skill ссылается на Core NFR
  как на источник метрик для сценариев (p95, RTO/RPO, SLO).
- **`nfr-requirements.md` (v1.0)** — непротиворечив. Указан как дополнительный
  вход.
- **`ai-protocols.mdc` (v1.0)** — skill соблюдает протокол версионирования
  (YAML front matter с version/lastUpdated) и протокол каноничности
  (ссылки на актуальные версии Core).
- **`code-style-dotnet.mdc` (v1.0)** — не затрагивается (skill не про код).
- **`assistant-style.mdc` (v1.0)** — непротиворечив.

### 3.2 Соответствие другим skills

| Skill | Статус | Комментарий |
|-------|--------|------------|
| `adr-authoring` | Совместим | ATAM — вход для ADR; нет дублирования. Чётко разные зоны: ATAM анализирует варианты, ADR фиксирует решение. |
| `architecture-review` | Совместим | Review — финальная проверка; ATAM — предварительный анализ компромиссов. Зоны не пересекаются. |
| `nfr-design` | Совместим | NFR Design задаёт метрики, ATAM использует их как меры в сценариях. Корректная зависимость. |
| `capacity-planning` | Совместим | Capacity Planning даёт таблицу нагрузки, ATAM может использовать её для сценариев Performance/Scalability. |

| `integration-patterns` | Совместим | Integration Patterns описывают тактики; ATAM оценивает их tradeoffs. |
| `domain-modeling-ddd` | Совместим | DDD даёт контексты и границы; ATAM проверяет, выдержат ли они NFR. |

## 5. Заключение

Skill `atam-tradeoff-analysis` — **сильное дополнение** к набору skills проекта.
Он закрывает ранее отсутствовавшую нишу: структурированный анализ компромиссов
между архитектурными вариантами до принятия решения (ADR).

**Рекомендация**: исправить критическое замечание C-1 (ссылки на `.cursor/...`),
устранить существенные замечания (P-1, P-2, A-1, A-2, C-2) и рассмотреть
рекомендательные. После этого skill готов к merge.
