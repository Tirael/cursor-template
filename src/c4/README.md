# Структура архитектурной документации EBookStore (v1.0)

## Описание структуры

C4/LikeC4 диаграммы хранятся в `src/c4/`.

Примеры проектов и сниппетов кода хранить в `src/examples/`:

- `.NET`: минимальный сервис/библиотека
- `Angular`: минимальное приложение/feature-модуль
- `Python`: утилиты/скрипты/PoC

## Структура файлов

```text
src/c4/
├── __spec.c4          # Спецификация стилей, элементов и отношений
├── model/             # Модель (C4 Level 1-3): пользователи, системы,
                       # контейнеры, компоненты, связи
├── views/             # Представления (views) для визуализации
└── *.svg              # Иконки/ресурсы для диаграмм
```

## Основные файлы

### `__spec.c4`

Спецификация стилей и определений элементов:

- Определения пользователей
- Определения элементов (database, cache, queue, etc.)
- Определения отношений
- Стили и иконки
- Теги для фильтрации

### `model/`

Модель системы, содержит:

- Определения пользователей
- Систему EBookStore со всеми контейнерами
- Функциональные модули
- Инфраструктурные компоненты
- Внешние системы
- Все связи между элементами

### `views/`

Представления для визуализации:

- **Context Diagrams** - контекстные диаграммы для разных пользователей
- **Container Diagrams** - контейнерные диаграммы
- **Infrastructure Diagrams** - инфраструктурные диаграммы

## Уровни детализации C4 Model

### Level 1: System Context (Контекст системы)

Контекстные диаграммы показывают систему в контексте её окружения.

- Определены в `views/`

### Level 2: Container (Контейнеры)

Контейнерные диаграммы показывают высокоуровневую архитектуру.

- Определены в `views/`

### Level 3: Component (Компоненты)

Компонентные диаграммы показывают внутреннюю структуру контейнеров.

- Планируется добавить отдельными `.c4` файлами по ключевым контейнерам

### Level 4: Code (Код)

Кодовый уровень обычно не фиксируется отдельными диаграммами в шаблоне,
так как исходный код является источником истины.

### Дополнительно: Deployment/Infrastructure (не уровень C4)

Диаграммы развертывания/инфраструктуры описывают среду исполнения
(например Kubernetes, окружения, внешние зависимости) и живут в `views/`.

## Работа с проектом

### Запуск LikeC4

Для визуализации диаграмм используйте Docker:

```bash
docker run --rm \
  -v $PWD/src/c4:/data \
  --init \
  -t \
  -p 5173:5173 \
  -p 24678:24678 \
  -e CHOKIDAR_USEPOLLING=1 \
  -e CHOKIDAR_INTERVAL=200 \
  likec4/likec4:1.48.0 \
  start
```

### Порядок чтения файлов

LikeC4 автоматически загружает все `.c4` файлы из директории `src/c4/`.

Рекомендуемый порядок:

1. `__spec.c4`
2. `model/**`
3. `views/**`
