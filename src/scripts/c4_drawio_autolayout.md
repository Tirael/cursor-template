# Алгоритм: auto-layout + routing для draw.io (v1.0)

Цель: сгенерировать `.drawio` (diagrams.net) для C4‑подобных диаграмм так, чтобы:

- элементы **не пересекались**;
- соединения **не пересекали элементы**;
- соединения **не пересекались между собой** (скрипт прокладывает их последовательно и резервирует занятое пространство).

## Входные данные

См. пример `src/examples/python/c4-drawio-autolayout/spec.json`.

## Размещение (layout)

Используется упрощённый вариант Sugiyama для направленного графа:

- **Оценка слоя (layer/rank)**: итеративная релаксация по рёбрам \(layer[target] = max(layer[target], layer[source] + 1)\) с ограничением числа итераций.
- **Слои → колонки**: каждому слою назначается своя колонка по X, узлы внутри слоя размещаются по Y с фиксированным шагом (гапы задаются флагами).
- **Снижение пересечений связей (crossing reduction)**: несколько проходов barycenter/median‑подобной эвристики сверху‑вниз и снизу‑вверх для переупорядочивания узлов внутри слоёв.

Это даёт воспроизводимую раскладку, близкую к оптимальной по эвристике минимизации пересечений для layered‑графов (типичный случай для C4 связей “слева‑направо”).

## Трассировка (routing)

Для каждой связи строится ортогональный маршрут по сетке:

- **Сетка**: шаг `cell` (по умолчанию 20px).
- **Препятствия**: прямоугольники элементов, увеличенные на `node-pad` (чтобы провода не “липли” к рамкам).
- **Поиск пути**: A* по 4‑связной решётке с Manhattan‑эвристикой.
- **Минимизация изгибов**: в стоимость шага добавляется `bend-penalty` при смене направления (состояние A* включает направление).
- **Запрет пересечений соединений**: после прокладки ребра его клетки (и радиус вокруг них) добавляются в `reserved`, что делает их препятствиями для следующих рёбер.
- **Если путь не найден**: выполняются повторные попытки с расширением рабочей области (`expand-tries`).

## Выход

Скрипт генерирует полноценный `.drawio` файл (mxfile) с компрессией, совместимый с diagrams.net.
