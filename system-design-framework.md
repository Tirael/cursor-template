# Framework проектирования системы (v1.0)

Этот документ задаёт **каноничный порядок** проектирования системы/модуля и набор минимальных артефактов.

## Вход

- Ключевые пользовательские сценарии (3–7)
- Ограничения (интеграции, регуляторика, сроки)
- Критичные NFR (см. `nfr-requirements.md`)

## Порядок

1. **Стоп‑кран**: зафиксировать, что именно меняем и последствия.
2. **Контекст**: границы системы и внешние зависимости (C4 Level 1).
3. **Контейнеры**: основные сервисы/хранилища/очереди и связи (C4 Level 2).
4. **Компоненты**: детализация ключевых контейнеров при необходимости (C4 Level 3).
5. **Данные**: владельцы данных по контекстам, консистентность, кэш/поиск.
6. **Интеграции**: sync/async, контракты, версионирование, идемпотентность.
7. **Безопасность**: authn/authz, tenant isolation, аудит, шифрование.
8. **Наблюдаемость**: логи/метрики/трейсы, SLI, алерты, health.
9. **Нагрузка**: сценарии, квоты, деградации, узкие места.
10. **Решения**: если есть выбор вариантов — запись решения и trade-offs.
11. **Review**: финальная проверка по чек‑листам.

## Минимальные артефакты

- C4 views в `src/c4/views/` (минимум: контекст + контейнеры)
- Таблица SLO/SLI в `nfr-requirements.md` или приложением к задаче
- Таблица нагрузки и квот (см. `.cursor/skills/capacity-planning/SKILL.md`)
- Список решений/компромиссов в `tradeoffs.md` и/или запись в `adr-architecture-decisions.md`
