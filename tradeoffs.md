# Каталог компромиссов (trade-offs) (v1.0)

Шаблон для фиксации решений в формате “что выигрываем / что теряем”.

## Консистентность данных

- **Strong consistency**
  - **Плюсы**: проще reasoning, меньше багов на чтение
  - **Минусы**: latency, сложнее масштабирование
- **Eventual consistency**
  - **Плюсы**: масштабирование, устойчивость, меньше связности
  - **Минусы**: сложнее UX (статусы), нужны ретраи/идемпотентность

## Кэширование

- **Cache-aside**
  - **Плюсы**: простой контроль, кэш не источник истины
  - **Минусы**: инвалидация сложная, возможен cache stampede
- **Write-through**
  - **Плюсы**: предсказуемость read-after-write
  - **Минусы**: усложняет запись и обработку ошибок

## Шардирование и репликация

- **Репликация чтения**
  - **Плюсы**: разгрузка primary, рост RPS чтений
  - **Минусы**: лаг реплик, read-after-write правила
- **Шардирование**
  - **Плюсы**: горизонтальный рост объёма и RPS
  - **Минусы**: операционная сложность, кросс-шардные запросы

## CQRS

- **Включать**
  - **Плюсы**: оптимизация read/write путей, независимое масштабирование
  - **Минусы**: удорожание, асинхронная проекция и рассинхронизация

## Очереди и асинхронность

- **Sync**
  - **Плюсы**: немедленный ответ, проще трассировка
  - **Минусы**: связь по доступности, таймауты, каскадные отказы
- **Async**
  - **Плюсы**: буферизация, устойчивость, throughput
  - **Минусы**: сложнее UX статусов, идемпотентность, лаги

## Retries/Timeouts/Circuit Breaker

- **Retries**
  - **Плюсы**: устойчивость к транзиентным ошибкам
  - **Минусы**: усиление нагрузки, нужен backoff и jitter
- **Timeouts**
  - **Плюсы**: защита ресурсов
  - **Минусы**: ошибки при пиках, нужен graceful degradation
- **Circuit breaker**
  - **Плюсы**: стоп каскадных отказов
  - **Минусы**: настройка порогов, риск ложных срабатываний
